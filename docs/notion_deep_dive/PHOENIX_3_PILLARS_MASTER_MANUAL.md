# 1. MASTER OPERATING THESIS

Traditional prep tools fail because:
1. Solving algorithms in isolation does not prepare candidates for live senior technical follow-up grilling.
2. Peer mock interviews lack experienced senior interviewer guidance and deep architectural counter-probes.
3. Hackathon teams suffer from arbitrary scope creep, unbalanced workload division, generic CRUD idea selection, and catastrophic stage presentations.
4. Candidates are blind to 4-year RSU equity vesting schedules, progressive marginal tax brackets, and cost-of-living purchasing power.

# 2. PILLAR 1: INTERVIEW PREP & MOCK DEFENSE OS (`/vault/interview`)

### Feature 1: WebRTC P2P Mock Video Rooms & Silent AI Sentinel
* **File**: `sup-backend/modules/interview-prep/peerInterviewMeshGateway.js` | `phoenix-ui/src/components/LivePeerRoom.jsx`
* **Crisis**: Peer interviewers do not know how to probe candidate solutions deeply.
* **Architecture**: Direct WebRTC media mesh (<50ms latency, $0 server egress). A background worker transcribes candidate speech, queries a Distributed Systems Knowledge Graph, and pushes counter-probes silently to the interviewer's screen in <15ms.
* **Key Function**: `generateAISentinelProbe(transcript, topic) -> { detectedTopic, suggestedProbe, dispatchTimestamp }`

### Feature 2: Distributed CRDT Collaborative Architecture & Code Canvas
* **File**: `sup-backend/modules/interview-prep/crdtCollaborativeCanvas.js` | `phoenix-ui/src/components/WhiteboardCanvas.jsx`
* **Crisis**: Concurrent code typing and architecture block dragging causes split-brain state overwrite in plain WebSockets.
* **Mathematical Moat**: State-based CRDTs with Lamport vector clocks:
  $$V_{\text{local}}[i] = \max(V_{\text{local}}[i], V_{\text{incoming}}[i]) + 1$$
  Mutations form a commutative semi-lattice with deterministic convergence.

### Feature 3: Multi-Hop Knowledge Graph Depth Prober
* **File**: `sup-backend/modules/interview-prep/depthProberEngine.js` | `aiAdaptiveKnowledgeProber.js`
* **Crisis**: Candidates memorize surface-level answers ("Use Redis") but fail on edge cases.
* **Function**: `probeDepth(topic, candidateResponse, currentDepthLevel) -> { nextHopConcept, adversarialQuestion, expectedMoat }`

### Feature 4: Real-Time Vocal Prosody, Speaking Pace (WPM) & Filler Word Analyzer
* **File**: `sup-backend/modules/interview-prep/speechEvaluatorEngine.js` | `phoenix-ui/src/components/SpeechTelemetry.jsx`
* **Mechanics**: Analyzes real-time WebAudio API stream for speech velocity (Words Per Minute), vocal jitter, pitch variance, and filler word frequency (um, uh, like). Flags high anxiety when $\text{WPM} > 180$ or filler density $> 8\%$.

### Feature 5: System Design SLA & Chaos Monkey Simulator
* **File**: `sup-backend/modules/interview-prep/systemDesignEvaluator.js` | `chaosEvents.js`
* **Mechanics**: Simulates live infrastructure disasters during architecture interviews: AZ-East datacenter partition, Redis cache failure, replication lag $> 2000\text{ms}$. Evaluates candidate mitigation responses.

# 3. PILLAR 2: HORIZON CAREER TRAJECTORY & FINANCIAL INTELLIGENCE (`/vault/horizon`)

### Feature 11: Progressive Multi-Slab Tax & 4-Year RSU Vesting PPP Normalizer
* **File**: `sup-backend/modules/interview-prep/equityTaxArbitrageEngine.js` | `phoenix-ui/src/components/EquityCalculator.jsx`
* **Problem**: Candidate evaluating Google Bangalore ₹45L CTC vs US Startup $135,000 in San Francisco does not know which offer yields higher real discretionary wealth.
* **Formulation**:
  $$\text{Gross} = \text{Base} + \text{Bonus} + \sum_{y=1}^{4} \frac{\text{RSU}}{4}$$
  $$\text{Post-Tax} = \text{Gross} - \sum_{i=1}^{k} \tau_i \cdot \max(0, \min(\text{Gross}, \text{Cap}_i) - \text{Floor}_i)$$
  $$\text{Real Disposable} = \frac{\text{Post-Tax Local}}{\text{PPP Factor}} - \text{Metro Living Cost}$$
* **Verdict**: Bangalore ₹45L delivers 38% higher real purchasing power than SF $135k after 32% California tax and $48k/yr rent.

### Feature 12: Karnataka KEA KCET/DCET State Rank Seat Matrix Engine
* **File**: `sup-backend/modules/interview-prep/seatMatrixEngine.js` | `phoenix-ui/src/components/SeatMatrixExplorer.jsx`
* **Mechanics**: Ingests historical cutoff datasets for 220+ engineering colleges across GM, 1G, 2A, 2B, 3A, 3B, SC, ST quota categories. Predicts exact seat allocation probabilities across round 1, round 2, and mop-up rounds.

### Feature 13: Corporate Offer Counter-Negotiation Script Generator
* **File**: `sup-backend/modules/interview-prep/compensationNegotiatorEngine.js` | `negotiationEngine.js`
* **Mechanics**: Generates mathematically calibrated, leverage-backed email negotiation scripts that ask for higher base or sign-on bonuses without risking offer rescission.
